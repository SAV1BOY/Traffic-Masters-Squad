# Template Usage Guide

## Purpose
How to use the squad's templates for consistent output quality.

## Available Templates

### Campaign Templates
- **Experiment Card** (`lib/components/experiment-card.md`): For documenting A/B tests
- **Creative Card** (`lib/components/creative-card.md`): For cataloging ad creatives
- **Ad Copy Component** (`lib/components/ad-copy-component.md`): For structuring copy

### Reporting Templates
- **Weekly Scorecard** (`data/metrics/weekly-scorecards.md`): Weekly performance
- **KPI Dashboard** (`data/metrics/kpi-dashboard-spec.md`): Dashboard structure

### Research Templates
- **Avatar/ICP** (`data/research/avatar-and-icp/index.md`): Customer profiles
- **Competitor Ads** (`data/research/competitor-ads/index.md`): Competitive intel

### Registry Templates
- All YAML files in `data/registries/` include schema definitions
- Follow the schema when adding new entries

## Template Rules
1. Never modify the template itself — copy it for each use
2. Fill in all required fields (marked in schema)
3. Use consistent naming conventions
4. Date-stamp all entries
5. Link to related registries using IDs

## Creating New Templates
- Follow existing template patterns
- Include field definitions and examples
- Get squad review before publishing
- Document in this guide
