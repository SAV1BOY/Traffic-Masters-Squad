## Purpose
Documents the evolution of a creative asset through iterations, tracking what changed between versions, the hypothesis behind each change, the result, the learning extracted, and the planned next iteration.

### Iteration Rules
1. Change only one element per iteration to isolate the variable.
2. Always compare against the current best performer, not the original V1.
3. Allow sufficient sample size before declaring a result.
4. Document every iteration, even if the change seems minor.
5. When a creative family is exhausted (3+ losing iterations), start a new family.

## Usage Notes
- Maintain one document per creative family throughout its lifecycle.
- Cross-reference with learnings-log-template.md for formal experiment records.
- Use taxonomy-tags.md to tag each iteration for aggregate analysis.

## Example
UGC video ad family: V1 (question hook, 60s) establishes baseline. V2 changes hook to bold stat (CPA drops 18%). V3 shortens to 30s (CPA neutral but reach increases). V4 tests new CTA (inconclusive). Next: test new visual opening.
